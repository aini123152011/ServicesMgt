# 网络规划

> 一次性说清：宿主网口怎么用、Docker 网络怎么分、13 个服务的端口怎么映射、被测 BMC 从哪个地址访问哪个夹具。
> 相关：接线与 macvlan 细节见 [部署指南](./deployment.md)「一之二」，二层网口绑定与校验的设计见
> `.trellis/tasks/09-23-host-nic-selection/`（形态甲）。

## 1. 宿主网口与两条访问路径

```
      管理网 / 办公网                              被测 BMC（管理口）
            │                                            │
            │ SSH、浏览器访问平台                          │ 一根网线（形态甲：直连测试口）
            ▼                                            ▼
 ┌──────────────────────────────────────────────────────────────────────────────┐
 │  夹具机 <管理网地址>（openEuler aarch64）                                  │
 │                                                                              │
 │   enp125s0f0                            enp125s0f1                            │
 │   <管理网地址>/20                    192.168.90.1/24                       │
 │   ├─ 管理网，默认路由走它                 ├─ 测试口，**不配默认网关**            │
 │   └─ 平台与全部服务在此发布端口           └─ 二层测试网段（192.168.90.0/24）     │
 │                                                                              │
 │   enp125s0f2 / enp125s0f3 / enp4s0f0np0 / enp4s0f1np1：空闲或已停用            │
 │   （enp125s0f3 原有 172.30.5.0/24 真实网段，已拔线并关闭自动连接）              │
 └──────────────────────────────────────────────────────────────────────────────┘
```

**两条路径互不影响**：接线不会改变管理网的地址与默认路由，平台与其他业务照旧；宿主机不做 IP 转发、
不做桥接，所以测试网段的流量不会漏进管理网（隔离，不是故障）。

## 2. Docker 网络规划

**每个服务一张独立 bridge 网络**——跨服务网络互不可见（隔离性可验证），平台与数据库共用一张网络；
每张网络同时启用 IPv6（ULA `fd00:30:<n>::/64`，宿主无全局 IPv6 时容器网络内可用真实 v6 客户端验证）。

```
┌─ 宿主网络命名空间 ──────────────────────────────────────────────────────────────┐
│                                                                                │
│  平台容器                每个服务容器（各自一张 bridge，互不可见）                 │
│  ┌──────────────────┐   ┌───────────────────────────────────────────────────┐  │
│  │ bmc-platform     │   │ chrony-net   172.30.1.0/24   fd00:30:1::/64       │  │
│  │ bmc-platform-pg  │   │ nginx-net    172.30.2.0/24   fd00:30:2::/64       │  │
│  │ 172.30.0.0/24    │   │ rsyslog-net  172.30.3.0/24   fd00:30:3::/64       │  │
│  │ fd00:30:0::/64   │   │ webdav-net   172.30.4.0/24   fd00:30:4::/64       │  │
│  └────────┬─────────┘   │ sftp-net     172.30.5.0/24   fd00:30:5::/64       │  │
│           │             │ vsftpd-net   172.30.6.0/24   fd00:30:6::/64       │  │
│           │ docker.sock │ tftpd-net    172.30.7.0/24   fd00:30:7::/64       │  │
│           └────────────►│ samba-net    172.30.8.0/24   fd00:30:8::/64       │  │
│      （平台通过 Docker  │ nfs-net      172.30.9.0/24   fd00:30:9::/64       │  │
│        API 管容器，不     │ snmptrapd-net 172.30.10.0/24 fd00:30:10::/64      │  │
│        需要加入各网络）   │ postfix-net  172.30.11.0/24  fd00:30:11::/64      │  │
│                         │ dhcp-net     172.30.12.0/24  fd00:30:12::/64      │  │
│                         │ freeradius-net 172.30.13.0/24 fd00:30:13::/64     │  │
│                         └───────────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────────────────────────────────┘
```

> 网段口径：`172.30.0.0/16` 在本机未被占用（`enp125s0f3` 停用后成立）；每张网络显式指定 /24，
> 因为宿主机已有大量网络，Docker 默认 /16 地址池已被分满。

## 3. 服务端口映射一览

宿主发布**统一范围 18101–18114**（便于文档化与防火墙放行）＋ **BMC 侧必须的标准端口**
（被测 BMC 通常只能填 IP，改不了端口）。

| 服务 | Docker 网络（网段 / IPv6） | 容器端口 | 宿主发布 | 生效方式 | 形态甲下 BMC 的入口 |
| --- | --- | --- | --- | --- | --- |
| chrony | chrony-net 172.30.1.0/24 · fd00:30:1::/64 | 123/udp | 123、18101 | 热重载 | `192.168.90.1:123/udp` |
| nginx | nginx-net 172.30.2.0/24 · fd00:30:2::/64 | 80、443 | 18102、18103 | 热重载 | —（不在 L2 集合内） |
| rsyslog | rsyslog-net 172.30.3.0/24 · fd00:30:3::/64 | 514/tcp+udp | 514、18104 | 重启 | `192.168.90.1:514` |
| webdav | webdav-net 172.30.4.0/24 · fd00:30:4::/64 | 8080 | 18105 | 重启 | — |
| sftp | sftp-net 172.30.5.0/24 · fd00:30:5::/64 | 22 | 18106 | 重启 | — |
| vsftpd | vsftpd-net 172.30.6.0/24 · fd00:30:6::/64 | 21、40000-40100 | 21、18107、40000-40100 | 重启 | — |
| tftpd-hpa | tftpd-net 172.30.7.0/24 · fd00:30:7::/64 | 69/udp | 69、18108 | 重启 | `192.168.90.1:69/udp` |
| samba | samba-net 172.30.8.0/24 · fd00:30:8::/64 | 445 | 445、18109 | 重启 | — |
| nfs-ganesha | nfs-net 172.30.9.0/24 · fd00:30:9::/64 | 2049 | 2049、18110 | 重启 | — |
| snmptrapd | snmptrapd-net 172.30.10.0/24 · fd00:30:10::/64 | 162/udp | 162、18111 | 重启 | — |
| postfix | postfix-net 172.30.11.0/24 · fd00:30:11::/64 | 25 | 25、18112 | 重启 | — |
| dhcp | dhcp-net 172.30.12.0/24 · fd00:30:12::/64 **＋ dhcp-l2-net（macvlan）** | 67/udp、547/udp、53/tcp+udp | **仅 18113（DNS）** | 重启 | `192.168.90.x:67`（DHCP）／`53`（DNS） |
| freeradius | freeradius-net 172.30.13.0/24 · fd00:30:13::/64 | 1812/udp、1813/udp | 1812、1813、18114 | 重启 | — |
| **平台** | bmc-platform-isolated-net 172.30.0.0/24 · fd00:30:0::/64 | 8000 | **18080** | — | 管理网访问，不经测试口 |

**两处例外要记住**：

- **dhcp 不发布 67/547**：DHCP 客户端从 `0.0.0.0` 广播到 `255.255.255.255`，Docker 的 NAT 端口发布
  只处理单播；且宿主机 53 端口被 libvirt 的 dnsmasq 占用（`192.168.122.1:53`），故只发布 18113。
- **挂 macvlan 的容器会失去宿主端口发布**（实测：DNAT 规则被移除），所以形态甲里只有 dhcp 走 macvlan，
  `tftpd-hpa`/`rsyslog`/`chrony` 保持宿主端口发布、由 BMC 经测试口地址访问。

## 4. 形态甲：BMC 侧的地址对照

```
被测 BMC（管理口）
 ├─ 取址：DHCPDISCOVER 广播 ──► enp125s0f1 ──► macvlan ──► bmc-dhcp 容器（192.168.90.x:67）
 │        DHCP 下发：地址 192.168.90.100-200、网关 192.168.90.1、DNS 192.168.90.x、可选 PXE 参数
 ├─ 域名解析：192.168.90.x:53（DNS，v4/v6 双栈）
 ├─ 取固件：tftp://192.168.90.1:69        （tftpd-hpa，宿主测试口地址）
 ├─ 发日志：192.168.90.1:514/udp          （rsyslog）
 └─ 对时：  192.168.90.1:123/udp          （chrony）
```

- `192.168.90.x`（macvlan 地址）= **dhcp 容器**在二层网段上的地址，由 `dhcp-l2-net` 分配。
- `192.168.90.1` = **宿主机测试口**地址，其余三个夹具的端口发布在 `0.0.0.0`，因此 BMC 用这个地址即可访问。
- 宿主机与其 macvlan 子接口之间默认不通，但本场景不需要它们互通（BMC 分别访问两边）。
- 平台仍从管理网（`<管理网地址>:18080`）访问；它通过 `docker.sock` 管容器，不依赖测试网段。

## 5. 启用/停用

```bash
# 启用二层（形态甲）
docker compose -f compose.yaml -f compose.l2.yaml up -d dhcp      # 只把 dhcp 挂 macvlan
# 测试口配址（一次性；**必须 never-default**，否则复现路由事故）
nmcli con mod <测试口> ipv4.addresses 192.168.90.1/24 ipv4.gateway "" ipv4.never-default yes
nmcli con up <测试口>

# 停用（回到纯容器网络）
docker compose -f compose.yaml up -d dhcp
nmcli con mod <测试口> ipv4.addresses "" ipv4.never-default yes && nmcli con up <测试口>
```

平台侧可在「关于 → 宿主网口」看到网口清单、当前绑定与一致性校验结果（地址池是否落在绑定口网段、
测试口是否承载默认路由等），详见 `.trellis/tasks/09-23-host-nic-selection/`。
